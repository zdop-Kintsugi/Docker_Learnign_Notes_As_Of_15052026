

Docker Swarm networking helps containers running on different servers communicate securely and reliably.

1. Two Types of Swarm Traffic
Control traffic → swarm management (join, leave, leader communication).
Always encrypted.
Application traffic → actual app/container data between services and users.
Main Networking Components
2. Overlay Network (Most Important)

An overlay network connects containers across multiple Docker hosts.

Used in production for:

Microservices communication
Backend APIs talking to databases
Service-to-service communication across nodes

Example:

docker network create --driver overlay my-network

Then attach services:

docker service create --network my-network nginx
Production Use
Web app ↔ API ↔ DB communication
Multi-node Kubernetes-like networking in Docker Swarm
Internal private communication
3. Ingress Network

Special overlay network used for:

Load balancing
Routing external traffic to service containers

Docker automatically:

Receives traffic on any swarm node
Uses IPVS load balancer
Sends request to an available container
Production Use

When users hit:

http://server:8080

Docker automatically routes traffic to healthy containers.

4. docker_gwbridge

Bridge between :

Overlay networks
Physical host network

It allows containers to access outside networks/internet.

Production Use
Container internet access
Communication between Docker host and overlay networks
Important Ports (Firewall)

Swarm nodes must allow :

Port					Purpose
7946 TCP/UDP			Node discovery
4789 UDP				Overlay network traffic

Production Use

Without these ports:

Nodes cannot communicate
Overlay networking fails
Service Discovery

Docker automatically finds services.

Two modes:

VIP Mode (Default)

Docker gives one virtual IP to a service.

Clients connect to :

my-service

Docker load balances internally.

Production Use

Simple internal load balancing.

DNSRR Mode

Docker returns multiple container IPs via DNS.

Used with external load balancers like:

HAProxy
Nginx
Traefik
Production Use

Better for :

Large-scale systems
Custom traffic routing
Encryption

Control traffic is always encrypted.

Application traffic is NOT encrypted by default.

Enable encryption :

docker network create --opt encrypted
Production Use

Needed for :

Sensitive internal traffic
Multi-datacenter communication
Compliance/security requirements
Important

Encryption adds performance overhead.

Overlay Network Size Limitation

Docker recommends :

/24 subnet

Meaning :

Around 256 IPs per overlay network
Production Use

For large systems :

Use multiple smaller overlay networks
Or external load balancers + DNSRR

Avoid huge subnets.

Publishing Ports

To expose services outside swarm :

docker service create -p 8080:80 nginx

Meaning :

External port 8080
Container port 80
Production Use

Expose:

Web apps
APIs
Public services

Separate Control and Data Traffic

Production clusters often use :

One network interface for management
Another network interface for application traffic

Example:

docker swarm init \
  --advertise-addr 10.0.0.1 \
  --data-path-addr 192.168.0.1
Production Use

Improves:

Performance
Security
Network isolation
