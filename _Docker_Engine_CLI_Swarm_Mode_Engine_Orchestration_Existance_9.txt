DOCKER ENGINE IN SWARM MODE 


Docker Swarm is Docker’s cluster management system.

Docker Swarm helps run Docker containers across multiple servers with:

Clustering
Load balancing
Auto-healing
Secure node joining
Overlay networking
High availability

Main workflow:

docker swarm init
docker service create
docker swarm join

It lets multiple Docker machines work together like one system.

Main Use
Run containers across many servers
High availability
Auto-recovery
Load balancing

Real Production Use Case
Running microservices in e-commerce apps
Hosting scalable APIs
Managing production clusters

Main Command
docker swarm init


Create a Swarm :

This command converts a Docker machine into a Swarm Manager.

Command
docker swarm init

What Happens Internally
Enables swarm mode
Creates cluster
Makes current node manager
Opens port 2377
Creates overlay network
Generates security tokens

Production Use Case

Used when setting up:

Kubernetes alternative
Multi-server Docker deployment
HA backend systems 


Join Worker Nodes :

Other servers can join the swarm as workers.

Command
docker swarm join --token <TOKEN> <MANAGER-IP>:2377

Worker Role
Runs containers/tasks
Receives instructions from manager

Production Use Case

Example:

1 manager
10 worker servers
Workers run app replicas


Join Manager Nodes :

Additional manager nodes improve fault tolerance.

Command
docker swarm join-token manager

Then use generated command.

Why Needed it is : 

If one manager crashes, another continues control.

Production Use Case

Critical systems:

Banking apps
Healthcare systems
Enterprise SaaS

Usually:

3 or 5 managers


Overlay Network :

Swarm automatically creates:

ingress

This is an overlay network.

Purpose

Allows containers on different servers to communicate.

Production Use Case

Frontend container on Server A talks to DB on Server B.

Command Example
docker network create -d overlay mynet


Default Address Pool :

Docker assigns IP ranges to overlay networks.

Default:

10.0.0.0/8

Sometimes this conflicts with company networks.

Custom Pool Command
docker swarm init --default-addr-pool 10.20.0.0/16

Production Use Case

Large enterprise networks with custom IP planning.


Custom Subnet Mask :

Controls subnet size.

Command
docker swarm init \
--default-addr-pool 10.20.0.0/16 \
--default-addr-pool-mask-length 24

If --default-addr-pool-mask-len were unspecified or set explicitly to 24, this would result in 256 /24 networks of the form 10.20.X.0/24.

docker swarm init --default-addr-pool 10.20.0.0/16 --default-addr-pool 10.30.0.0/16 --default-addr-pool-mask-length 26

The math in your example is spot on:Net1 gets the first slice: 10.20.0.0/26 (Range: .0 to .63).Net2 gets the next slice: 10.20.0.64/26 (Range: .64 to .127).
Docker will continue through the 10.20.0.0/16 range before it even touches the 10.30.0.0/16 pool.

This command creates a massive "bucket" of IP addresses and defines exactly how large each individual "slice" (overlay network) should be when it is created. Exhaustion: Docker will fully use the first pool (10.20.0.0/16) before it starts pulling from the second pool (10.30.0.0/16). You cannot change these pools after you run docker swarm init. If you need to change them later, you have to leave the swarm and re-initialize it.


By using two /16 pools and a /26 mask length, you are creating a very specific set of limits:Total IP Range: Everything from 10.20.0.0 to 10.20.255.255 and 10.30.0.0 to 10.30.255.255.Individual Network Size: Each overlay network created will have exactly 64 IP addresses (a /26 subnet).Maximum Networks: You can create 2,048 separate overlay networks (1,024 from each /16 pool) before you run out of addresses.

Meaning

Creates many smaller networks.

Production Use Case

Multi-team environments :

Team A network
Team B network
Isolated services


Advertise Address : 

Manager must expose reachable IP to other nodes.

Command
docker swarm init --advertise-addr 192.168.1.10
Why Important?

Needed in:

Cloud
Multi-region setup
Multiple NIC servers
Production Use Case

AWS / Azure clusters with private-public IPs.


View Join Token :

Shows token needed for joining nodes.

Worker Token
docker swarm join-token worker
Manager Token
docker swarm join-token manager

Production Use Case

Secure onboarding of new servers.


Quiet Token Output : 

Shows only token.

Command
docker swarm join-token --quiet worker

Production Use Case

Automation scripts:

CI/CD pipelines
Terraform
Ansible

Rotate Tokens :

Old token becomes invalid.

Command
docker swarm join-token --rotate worker
Why?

Security best practice.

Production Use Case

After:

Security breach
Employee exit
Token leak



Security Notes :

Join tokens are secrets.

Never
Push to GitHub
Share publicly
Store in logs
Best Practice

Rotate every:

6 months
Production Use Case

Enterprise DevSecOps compliance.
