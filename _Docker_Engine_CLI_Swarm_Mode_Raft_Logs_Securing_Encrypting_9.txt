DOCKER LOCK RAFT LOGS WITH ENCRYPTION KEY

Swarm managers use Raft logs to store cluster state, and these logs are encrypted at rest by default.

This protects sensitive service configuration and secrets from attackers who gain disk access.

On restart, Docker loads two keys into memory:

The mutual TLS key (for secure node-to-node communication).

The Raft log encryption key (for decrypting logs).

With autolock enabled, managers require manual unlocking after restart using a key encryption key (KEK).
When Docker restarts, both the TLS key used to encrypt communication among swarm nodes and the key used to encrypt and decrypt Raft logs on disk are loaded into each manager node's memory. 
When Docker restarts, you must unlock the swarm first, using a key encryption key generated by Docker when the swarm was locked. You can rotate this key encryption key at any time.

You can rotate the KEK anytime for added security.

New nodes joining the swarm don’t need manual unlocking — the key is securely propagated via mutual TLS.

This feature was introduced to support Docker secrets, ensuring sensitive data remains protected even if disk files are exposed.

Secrets Protection : Ensures passwords, API keys, and certificates stored in Raft logs remain unreadable if disks are compromised.

Compliance Requirements : Meets enterprise security standards (e.g., PCI-DSS, HIPAA) by enforcing encryption and manual unlock.

Disaster Recovery : Prevents unauthorized access to cluster state after a crash or reboot until admins unlock managers.

Key Rotation : Regularly rotate KEKs to reduce risk of long-term exposure.

High-Security Environments : In financial or government workloads, autolock ensures nodes cannot auto-start without admin intervention.


Initialize a swarm with autolocking enabled :

We can initialize a new swarm with autolock enabled using. 

docker swarm init --autolock

This ensures that when Docker restarts, manager nodes remain locked until manually unlocked.

Unlocking requires a key encryption key (KEK) generated at initialization, which must be stored securely (e.g., password manager).

If the swarm is locked, attempts to restart services will fail until unlocked with.

docker swarm unlock

Worker and manager nodes can still be added using join tokens, but only managers require manual unlock after restart.

This feature protects sensitive Raft logs and TLS keys at rest, preventing unauthorized access if a node is compromised.


Enable or disable autolock on an existing swarm :

This ensures manager nodes require manual unlocking after restart with a key encryption key (KEK).

The KEK must be stored securely (e.g., password manager), otherwise managers cannot restart.

To disable autolock, set --autolock=false, which stores TLS and Raft encryption keys unencrypted on disk.

Disabling autolock trades off security vs convenience: easier restarts but less protection for secrets and Raft logs.

Keep the unlock key temporarily after disabling autolock, in case a manager still expects the old key.

This feature balances operational ease with strong at-rest encryption for sensitive cluster data.

To enable autolock of raft key

docker swarm update --autolock=true

To disable autolock raft key

docker swarm update --autolock=false

Enable autolock when handling sensitive workloads, compliance requirements, or production clusters.

Disable autolock in dev/test environments where convenience outweighs security.

Always store unlock keys securely (password manager, HSM).

Keep old keys briefly after disabling autolock, in case a manager still expects them.

Regularly rotate unlock keys to reduce long-term exposure risks.

Current unlock key for a running swarm and rotate the key :

Swarm managers use an unlock key (KEK) to decrypt Raft logs and credentials after restart.

If a manager node goes down and comes back, you must unlock it with the current key using.

docker swarm unlock-key

The key must be stored securely (e.g., password manager), otherwise the manager cannot restart.

We can rotate the unlock key anytime with

docker swarm unlock-key --rotate

Rotation enhances security but requires keeping the old key briefly, in case a manager still needs it before receiving the new one.

If the key was rotated and lost, you may need to force the node to leave and rejoin as a new manager.

This mechanism ensures encrypted Raft logs and secrets remain protected even during node failures or restarts.
